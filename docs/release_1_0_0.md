# Public TGLC 1.0 roadmap

This document records future calibration and API-stability work after the
0.8.0 correction release. It is not the shipping checklist for 0.8.0: that
bounded scope and its validation status are in [release_0_8_0.md](release_0_8_0.md).
The package now uses version **0.8.0** and processing convention
**spoc-0.8.0**. Public and MIT QLP packages both install as `tglc`; use separate
environments and identify the repository and processing version when comparing
products. Existing MAST products are not regenerated by a package upgrade.

## Consolidation status

Validation of the assembled correction implementation recorded 105 passing
offline tests and one explicit
strict expected failure. The suite covers independent interpolation, masks,
proper motion, crowded injection cases, public APIs, source/ePSF caches, and FITS
round trips. A separate 24-cadence sample from saved SPOC S54/S80 cutouts produces
24 finite fits with smaller image residuals and verified output/cache reuse.
These are integration checks, not a new full-sector scientific calibration.

Subsequent real-signal comparisons cover WASP-4 b and WASP-18 b in S2,
TOI-519 b in S7 (90x90 SPOC cutouts), and the IPHAS J1908 stellar eclipse in
S54/S80. PSF residual scatter improves and the stellar eclipse is retained,
but catalog-normalized planet amplitudes do not uniformly improve. In
WASP-18, catalog anchoring changes an otherwise close raw PSF transit contrast;
in TOI-519, the changed aperture fraction shifts fractional depth despite a
nearly unchanged absolute aperture decrement. Validate final normalization
and detrended products with independent signal tests before making broader
1.0 calibration claims. These limitations are documented for 0.8.0, whose raw
flux and offsets remain available for custom calibration.
Preliminary real-pixel power/edge-prior grids show coupled tradeoffs;
retain power 1.4 and edge_compression 1e-4 pending broader calibration.

The remaining depth test identifies variable-target feedback in a small,
12-star synthetic field. The original fixture uses target-normalized flux
ratios; with production's brightest-star normalization, a 1% transit is
recovered as 0.831622% in aperture flux and 0.744553% in PSF flux. This is a
sparse-calibrator stress case, not evidence for a comparable bias in typical
TGLC products or a sufficient reason to require target exclusion before release.

A controlled follow-up keeps the same target and bright neighbor but adds
constant stars elsewhere. With 200 stars in 150x150 pixels, median recovered
depths are 0.996981% and 0.995010%; with 1,000 stars in 300x300 pixels, they are
0.999363% and 0.999430% (three realizations; added stars span 0.3-3 times the
target flux). Thus more informative stellar constraints strongly dilute this
effect. Raw catalog count alone is insufficient: very faint added stars help
less, while crowding changes pixel weights and masks. These noiseless,
spatially constant-PSF tests establish the mechanism, not an optimal cutout size.
Use representative SPOC injection recovery, including real spatial/temporal PSF
variation and brightness distributions, to set practical release tolerances.

The checklist below is a future work inventory. Its unchecked items are not
uncompleted component tests or prerequisites for 0.8.0; several component
regressions already pass, while broader calibration remains to be done.

## Scope and compatibility

The public release should provide a reliable archive-backed, single-target SPOC
workflow with stable Python entry points, interpretable FITS outputs, and useful
errors. Adopt independently verified numerical and engineering improvements from
MKI while retaining the public workflow. MIT database access, GPU acceleration,
QLP-specific pipeline layout, and a wholesale API replacement are not required
for this release.

Proposed supported entry points are `tglc_lc`, `get_tglc_lc(method="query")`,
`plot_lc`, `plot_pf_lc`, `plot_contamination`, and `plot_epsf`. Existing call
signatures should remain usable where possible. Path arguments accept strings or
`pathlib.Path`. Extraction returns the generated FITS paths. TICA remains
experimental unless its separate data-ingestion and timing gates pass. Personal
batch recipes, `plot_aperture`, and `choose_prior` need replacement or explicit
legacy documentation before they can be advertised as general-purpose APIs.

New files are separated by product under `lc/SPOC/` and `lc/TICA/`; legacy files
are retained in place. Plotting defaults can discover both, so comparisons must
select a product and processing version explicitly. New ePSF caches contain
fingerprints and configuration metadata. Never reuse a legacy cache merely
because its filename or array shape matches.

## Future scientific validation

- [ ] Verify interpolation against an independent arbitrary-kernel oracle,
  including x/y ordering, integer and half-pixel boundaries, continuity, and
  target reconstruction. The original coordinate mapping and MKI node-weight
  errors require distinct regressions.
- [ ] Verify weighting and regularization under a consistent flux-unit change;
  compare recovered PSF wings as well as numerical residuals. Do not select a
  regularization strength using unit invariance alone.
- [ ] Exclude non-finite, zero-weight, saturated, and explicitly masked pixels
  consistently in ePSF and target fits. Test saturated cores and bleed neighbors,
  edge dilation, all-masked frames, singular fits, and failure propagation.
  The configurable default 80000 e-/s cutoff is conservative and approximate;
  validate it across cameras and CCDs before freezing it as a release default.
- [ ] Validate proper-motion propagation and Gaia identities, including high
  proper motion, high declination, missing motion, and archive outage cases.
  Missing DR2-to-DR3 matches must remain unknown rather than relabeled identities.
- [ ] Test catalog halos and edge extraction with bright/variable sources just
  outside the cutout. Separate model contributors from extraction targets.
- [ ] Inject known transits/variability and recover depth, amplitude, and baseline
  across subpixel phases, aperture sizes, PSF widths, and contamination levels.
  Aperture fractions must use the full supported PSF rather than a cropped 5x5
  normalization. Explicitly define flux outside modeled support.
- [ ] Preserve spacecraft and processing flags through a full FITS round trip.
  Invalid/saturated aperture samples must not become apparently good zeros.
  Test constant-background, NaN-background, and no-good-reference cases.
- [ ] Exercise fixed-neighbor and floating-prior extraction through actual FITS
  writing, including absent diagnostics and failed fits.
- [ ] Verify time systems, spacecraft ephemeris coverage, exposure metadata, and
  barycentric correction against an independent reference. SPOC cutout timestamps
  are already barycentric at the cutout reference; validate the remaining
  reference-to-target correction rather than applying a second full correction
  or silently querying Horizons. If retaining TICA,
  support its historical headers/filenames or enforce an explicit support range.
- [ ] Document raw, background-corrected, aperture-normalized, and detrended flux
  definitions. Distinguish scatter estimates from propagated measurement errors;
  document any uncertainty columns that remain unavailable.

## Validation evidence

- [ ] Convert prior negative reproductions into desired-behavior regression
  tests. Existing test agreement is not proof of scientific correctness.
- [ ] Assemble a small archived benchmark with quiet stars, injected transits,
  variable neighbors, high proper motion, crowded fields, saturated stars,
  detector/cutout edges, and representative early/recent SPOC sectors.
- [ ] Compare the same inputs with published 0.7.2 and corrected processing;
  record residual images, recovered depth, scatter, usable cadences, fit failures,
  catalog positions, cache configuration, exact versions, and runtime/memory.
  Set acceptance tolerances before evaluating the final benchmark.
- [ ] Keep network tests separately marked. Run a fresh single-target download
  as an explicit integration gate; default tests must run without services.
- [ ] Independently inspect representative FITS files and tutorial figures.
  State which data modes and numerical cases were not exercised.

## Maintenance and the eventual 1.0 release

- [ ] Use one authoritative package version across distribution metadata,
  `tglc.__version__`, documentation, and FITS provenance; finalize the processing
  schema/version alongside the scientific changes.
- [ ] Build wheel and sdist, check metadata, install the wheel into a clean
  environment, and verify the bundled background mask and ephemeris data.
- [ ] Run the offline suite on supported Python 3.10–3.12 and Linux/macOS. Widen
  NumPy/Astropy/Python constraints only after testing the proposed matrix.
- [ ] Run public API examples with integer, NumPy-integer, bare-string, and
  prefixed TIC IDs, ordinary and `Path` directories, multiple sectors, and
  product-filtered plotting. Validate target identity in the resulting FITS.
- [ ] Replace documentation placeholders and stale platform/version statements.
  Explain saturation limitations, priors, caches, flags, flux choice, detrending,
  units, time systems, data downloads, and expected failure handling.
- [ ] Restrict warning handling to specific known conditions; avoid silently
  suppressing diagnostic warnings from unrelated user code.
- [ ] Review the final diff for credentials, environments, downloaded science
  inputs, build artifacts, and personal analysis files before committing.

## Eventual 1.0 release sequence

1. Finish the bounded correctness fixes and API/output contract; record which
   MKI changes are adopted, deferred, or inapplicable to the public package.
2. Run synthetic and representative real-data validation and review its results.
3. Freeze a candidate, update the changelog with scientific changes and cache/
   output migration instructions, then build `1.0.0rc1` for external testing.
4. Install the candidate from its distribution artifact and rerun the documented
   quickstart in a clean environment. Resolve candidate failures before promotion.
5. Tag and publish 1.0.0, archive the release and validation record, update
   documentation/citation metadata, and state clearly which older generated
   products need reprocessing. Publishing is a separate explicit action.

Do not interpret package version 1.0.0 as a claim that historical light curves
were regenerated or that every optional data mode is validated.
